# 公開の手順（段階7）：個人の Vercel アカウントに公開する

自分でやるのは、アカウントの作成と、キーを画面に入れることだけです。**キーや秘密の値は、チャットにも、スクリーンショットにも貼りません。**
AI（Anthropic）は、段階5を飛ばしたので、**ルール版だけで公開します。`ANTHROPIC_API_KEY` は入れません。**

## 0. 環境変数：入れる名前と、ブラウザに出てよいか

Vercel の **Settings → Environment Variables** に、自分で入れます（Environments は **Production・Preview・Development** の3つにチェック）。

| 名前 | 入れるもの | ブラウザに出て |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase の Project URL（`https://xxxx.supabase.co`） | **よい**（頭に `NEXT_PUBLIC_` が付く値は、ブラウザに出ます） |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon キー（`eyJ…`）または publishable キー（`sb_publishable_…`） | **よい**（権限は RLS で守っています） |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role キー（`eyJ…`）または secret キー（`sb_secret_…`） | **出してはいけない**（RLS を通り抜けます。`NEXT_PUBLIC_` を付けない） |
| `NEXT_PUBLIC_SITE_URL` | 公開URL（`https://…vercel.app`。最後に `/` を付けない） | よい |

**入れないもの**：`ANTHROPIC_API_KEY`、`ANTHROPIC_MODEL`（AI は使いません）、`UNSPLASH_ACCESS_KEY`（写真の取得は、手元で seed を作るときだけ）。

- よくある間違い：service_role キーに `NEXT_PUBLIC_` を付ける／anon と service_role を逆に入れる。ビルドの最初に、`scripts/verify-env.mjs` が確かめて、間違いや足りないものがあれば **ビルドを止めて**、何を直すかを表示します（値は表示しません）。
- `NEXT_PUBLIC_` の値は、**ビルドのときに埋め込まれます**。あとから変えたら、**Redeploy** が必要です。

## 1. GitHub に上げる（まだなら）
1. GitHub で、**空の**リポジトリを作る（README などは付けない）。
2. 手元で：
   ```
   cd /Users/chika/tabi-on
   git remote add origin <リポジトリのURL>
   git push -u origin main
   ```
   （`.env.local` は `.gitignore` で除外されていて、上がりません。）

## 2. Supabase（本番）の準備
いま使っている Supabase のプロジェクトを、そのまま本番にします（開発の記録と同じ場所に入ります。分けたいときは、新しいプロジェクトに `supabase/setup.sql` を貼ります）。
1. すでに流した SQL は、流し直しません。まだ流していないものがあれば、順番に1回だけ：`setup.sql`（初めて）、または `apply-stage3.sql` → `apply-free-places.sql` → `apply-realtime.sql`。
2. Table Editor で、`spots` が **56件**。
3. Authentication の設定（Anonymous オン、Email オン、確認メールの文面）は、`supabase/README.md` のとおり。
4. **公開の前に**、Authentication → **SMTP Settings** で、自分のメール送信サービスを設定する（標準の送信は、送れる数が少ないため）。

## 3. Vercel に公開する
1. [vercel.com](https://vercel.com) に、**個人の GitHub アカウント**でサインアップ（Hobby プラン。会社のチームには入れない）。
2. **Add New → Project** → 上のリポジトリを **Import**。
3. 設定の画面で：
   - **Framework Preset**：Next.js（自動）。Build / Install のコマンドは、そのまま（`pnpm` は、`package.json` から自動で選ばれます）。
   - **Environment Variables**：上の表の4つを入れる（`NEXT_PUBLIC_SITE_URL` は、公開URLが決まってから、手順5で入れて構いません）。
4. **Deploy**。ビルドが「環境変数が足りません」で止まったら、表示された名前を Settings で直して、**Redeploy**。
5. 公開URL（`https://（プロジェクト名）.vercel.app`）が決まったら：
   - Vercel の **Settings → Environment Variables** に `NEXT_PUBLIC_SITE_URL` = その URL を入れる → **Deployments → 最新 → Redeploy**。
6. Vercel の **Settings → General → Node.js Version** は、**20.x か 22.x**。
7. （おすすめ）**Settings → Functions → Region** を、Supabase のプロジェクトの地域に近いところにする（日本なら Tokyo）。
8. 非公開のままにならないか：**シークレットウィンドウ**で公開URLを開き、ログインなしでたびおんが開くこと。開かない場合は、Settings → **Deployment Protection** を確かめる（本番のURLは、公開にする）。

## 4. 公開URLを Supabase に教える（メールのリンクの戻り先）
Supabase → **Authentication → URL Configuration**
1. **Site URL**：公開URL（`https://（プロジェクト名）.vercel.app`）に変える。
2. **Redirect URLs** に **追加**（いまある `http://localhost:3000/**` は、消さない）：
   - `https://（プロジェクト名）.vercel.app/**`
3. **Save**。
- これを忘れると、メールのリンクを開いても、アカウントができません（Site URL に戻されます）。
- Vercel のプレビュー（ブランチごとのURL）でもメールを試したいときは、`https://*-（アカウント名）.vercel.app/**` も追加します（任意）。

## 5. 公開したあとの機械的な確認（手元から）
```
node scripts/check-deploy.mjs https://（プロジェクト名）.vercel.app
```
画面が開く／manifest とアイコン／ブラウザに出る JavaScript に秘密の値がない／ログイン前でも spots が56件読めて trips などは読めない／匿名ログインとメールがオンで Google がオフ、を外から確かめます。**キーは表示しません。**

## 6. iPhone の Safari で確かめるチェックリスト（公開URLで）
**ホーム画面・開き方**
- [ ] 公開URLを開くと、旅の一覧（まだ旅がなければ「まだ旅はありません」）が出る。
- [ ] 共有ボタン →「ホーム画面に追加」で、アイコンが**たびおん**になり、名前も「たびおん」。
- [ ] ホーム画面から開くと、アドレスバーなしで開く。

**見た目（390×844 に近い画面）**
- [ ] どの画面でも、ヘッダーがステータスバー・ダイナミックアイランドと重ならない。スクロールしてもヘッダーは動かない。
- [ ] メインボタンとタブバーが、画面の下のホームインジケーターと重ならない。
- [ ] 見る画面（旅・マイページなど）にだけ、下のタブバーがある。旅を進める画面（旅をはじめる〜行きたい度合い）にはない。
- [ ] 文字が小さすぎず、押せるものが押しやすい。横にスクロールしない。

**旅を進める（2台で。1台目＝自分、2台目＝友だち役の別のブラウザかスマホ）**
- [ ] 1台目：「旅をはじめる」→ 友人を選んで名前を入れ、「次へ：招待コードを発行する」→ 招待コードが出る。
- [ ] 「LINEで送る」で、LINE が開く。**LINE に届いたリンクを開くと、アプリなしで参加の画面が開く**（リンクの見た目に「たびおん」が出る）。
- [ ] 2台目：名前を選んで「参加して質問に答える」。1台目の参加状況が、画面を読み込み直さずに「回答中」になる。
- [ ] 質問はどれもとばせる。日帰りを選ぶと宿の問いが出ない。時期が冬なら、問5が冬の選択肢になる。
- [ ] 問12：候補にない場所（例：熊野古道）を「そのまま追加」でき、削除もできる。
- [ ] 行きたい度合いを押すと、カードが飛んで次が出る。「次へ」ボタンはない。ほかの人の選択は、まったく出ない。
- [ ] 2人目が終えると、1台目の工程案に「2人目の回答で更新しました」が出る。
- [ ] 工程案：つかんで並べ替え／「ひとつ上へ・下へ」／「別の日に移す」／「この予定を外す」（5秒は「元に戻す」）／「＋ 候補から足す」。サイトにない場所の予定も、地図リンクが開く。
- [ ] 予定を押すと、写真・説明・住所・営業時間・料金・地図リンクの詳細が出る。
- [ ] 途中で閉じても、「旅」タブから続きを始められる。

**マイページ・アカウント**
- [ ] マイページ：「まだ行けていない場所」に、「行きたい」以上を選んだ場所だけが出る。M4 で「行った」にすると消える。
- [ ] 「行った」→「また行きたい」を選ぶと、チップが塗りつぶされ、「『また行きたい』で記録しました」と出る。再読み込みしても残る。
- [ ] 「ここへの旅をつくる」で、その場所が入った「旅をはじめる」が開く。
- [ ] 「メールで続ける」→ 確認メールが**届く**（迷惑メールも見る）→ リンクを開くと、マイページに戻って「アカウントができました。」、メールアドレスと「ログアウト」が出る。
- [ ] 別のブラウザで、同じメールの「メールで続ける」→ ログイン用のリンクが届き、開くと、同じ旅と「まだ行けていない場所」が見える。

**AI（段階5を飛ばしたので）**
- [ ] 「あなたへのおすすめ」の印は、どこにも出ない（ルール版）。これは、いまは正しい状態。

## 7. 公開後に確かめること（仕様書より）
- iPhone で、「ホーム画面に追加」でアイコンがたびおんになる（上の1つ目）。
- LINE で招待リンクを送り、受け取った側がアプリなしで参加できる（上の2つ目）。
- Anthropic Console の利用額：**AI を使わないので、0円のまま**のはず。
